# NEXT F CMS v1.0.57 — Summary Card Cleanup

Canonical parent: **v1.0.56**. Frontend-only UI cleanup; no D1 migration, Worker contract change, binding change or new secret.

## Why this release exists

v1.0.56 removed the footer/detail contract from the shared `MetricCard`, but several Gaming workspaces still used feature-local KPI components with their own `<small>` helper line. Those cards looked like metric cards but were not instances of `MetricCard`, so the first guard did not cover them.

## Change

Top-level KPI/overview/summary cards now use **label + value + optional icon only** across:

- Commerce Dashboard;
- Live Operations;
- Storefront Merchandising;
- Promotions & Campaigns;
- Commerce Analytics;
- Customers;
- Support & Disputes;
- Customer Reviews;
- Platform System Health hero metrics;
- Website Platform header stat.

Operational detail remains in queues, tables, status rows, alerts and drill-down panels where it changes an operator decision.

## Additional UI fixes

- `Open Live Operations` now uses the normal secondary-button treatment instead of a text-like ghost action.
- Catalog rows-per-page is a single compact custom select (`50 rows`, `100 rows`, `200 rows`) instead of a separate label plus narrow value control.
- Feature-local summary cards use tighter minimum heights now that the footer line is gone.

## Prevention

`npm run check:ui-hygiene` now checks both the shared `MetricCard` and the known feature-local KPI/overview card contracts. New sections should use `MetricCard` whenever possible; interactive summary filters may use local buttons but must not add a helper/footer line under the value.

## Scope

No business metric, API call, permission, integration, order state, supplier state or production data source is changed. This release changes presentation only.
