# NEXT F CMS v1.0.52 — Reviews Bridge Recovery

Canonical parent: **v1.0.51**. This release pairs with Gaming API v1.8.28.

## Changes

- CMS review listing and moderation use `GAMING_CMS_REVIEWS_TOKEN` instead of the promotion credential. The same strong random value is configured as a Worker secret on `nextf-cms-api` and `nextf-gaming-api`.
- The new credential is accepted only on Gaming review list and decision routes. Existing commerce and operations credentials and their other routes remain unchanged.
- When review loading fails, summary counts and the queue show an unavailable state rather than a false zero.

## Deployment and verification

Configure the new secret on both Workers, deploy the Gaming API before the CMS API, then deploy CMS Pages. The production Reviews list was verified to load an empty queue rather than `GAMING_CONTROL_NOT_CONFIGURED`. With no review records present, moderation decisions were not exercised in production.

No D1 migration. No secret value is stored in source or documentation.
