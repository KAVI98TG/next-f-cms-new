# NEXT F CMS V1.0.0 — Production Purity Manual Inspection

This package is a production-purity inspection candidate. Do not deploy it until the source checks, production data-hygiene scan, and browser inspection are green.

## 1. Install and source checks

```powershell
npm ci
npm run check:production-purity
npm run acceptance:source
```

Expected production-purity result: `32 passed, 0 failed`.

## 2. Authenticate for the read-only production data scan

```powershell
cloudflared access login https://cms-api.nextf.lk
$env:NEXTF_ACCESS_TOKEN = (cloudflared access token -app=https://cms-api.nextf.lk).Trim()
```

Do not print or paste the token.

## 3. Read-only production data-hygiene scan

```powershell
npm run production:data-hygiene:scan
```

The scan makes no changes. Review every finding:

- `SAFE_FIXTURE_ROWS` — recognized test/prototype rows eligible for guarded cleanup after review.
- `REVIEW` — never auto-delete. Inspect manually.
- `staff_identity_bindings` and unknown records are protected and never modified by this tool.

Do **not** run cleanup until the scan output has been reviewed.

## 4. Manual browser inspection

Open `https://cms.nextf.lk` and verify:

- Account/user menu is visible in the top bar.
- Account menu shows the verified Cloudflare Access session, environment, role, and email.
- `Sign out` is visible and uses Cloudflare Access logout.
- No production page says `Local development`, `Production deferred`, or `Production authentication not connected` as its runtime state.
- Platform Dashboard does not show hard-coded mock Recent Activity.
- Empty audit/activity data is represented honestly as empty, not replaced with fixtures.
- Platform Settings does not expose a production reset-data action.
- Gaming vNext does not expose a production `Reset prototype` action.
- Security identifies Cloudflare Access as the authentication/MFA/session authority instead of pretending browser controls configure Access.
- Backup/Recovery identifies D1 Time Travel as production disaster recovery; browser restore/import controls are not presented as production recovery.
- Digital, Gaming, Gaming vNext, and Software simulated external actions are disabled/fail closed unless their real integration capability is connected.
- Deep-route refresh works.
- Light/dark/system themes work.
- DevTools has no repeating CORS, 401/403, runtime, or network loops.

## 5. Guarded fixture cleanup — only after review

Only after the scan output has been reviewed and only if all findings to remove are classified `SAFE_FIXTURE_ROWS`:

```powershell
$env:NEXTF_ALLOW_PROD_FIXTURE_CLEANUP = "YES"
npm run production:data-hygiene:cleanup
Remove-Item Env:NEXTF_ALLOW_PROD_FIXTURE_CLEANUP
npm run production:data-hygiene:scan
```

The cleanup tool only removes recognized fixture rows from eligible app documents. It skips `REVIEW` findings and unknown records.

## 6. Stop before deployment

Send the hygiene scan output and any browser findings for review. Do not deploy this package merely because the source checks pass.
