# NEXT F CMS v1.0.34 - Supplier Funding Bridge + UI Hotfix

## Scope

This hotfix preserves the v1.0.33 FazerCards funding and payment-safety implementation while improving production diagnostics and the Suppliers control-plane UI.

## Changes

- Maps Gaming API funding query failures through `GamingControlError` to canonical staff API problem responses instead of collapsing them into `INTERNAL_ERROR`.
- Keeps funding commands protected by both `gaming.suppliers.manage` and `gaming.finance.manage`.
- Reworks the FazerCards funding panel into a compact two-column operational workspace.
- Distinguishes live funding balance from the last known provider-health balance.
- Shows a clear funding-bridge health state and payment-method count.
- Converts server credential failures into an operator-facing bridge warning without exposing any secret value.
- Prevents Add funds while the bridge is unhealthy.

## Production configuration requirement

`GAMING_CMS_SUPPLIER_FUNDING_TOKEN` must exist on both `nextf-cms-api` and `nextf-gaming-api` and must have the same value. Rotate both together when the current values cannot be confirmed.

## No migration

No D1 migration is required.
