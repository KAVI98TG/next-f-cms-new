# NEXT F CMS v1.0.55 — CMS UI Clarity System

Canonical parent: **v1.0.54**. Current v1.0.55 state: **candidate / non-canonical**. Contract registry remains **Production v1.2.0** at `https://contracts.nextf.lk/`.

## Scope

This is a frontend/design-system and UI-content hygiene release. It does not change production D1 schema, Worker API contracts, secrets, historical business data, review moderation behavior, supplier funding behavior, Checkout behavior, or public Gaming contracts.

## UI changes

- Removes the global Page Guide and keyboard-help chrome from the CMS shell. Global search, theme, notifications and account controls remain.
- Removes workspace-description microcopy from the sidebar so navigation is label-first and easier to scan.
- Raises internal CMS typography: normal secondary copy is 14 px, the absolute internal floor is 12 px, 12 px is reserved for sparse micro labels, and the inconsistent 13 px tier is removed.
- Cleans developer-facing architecture, roadmap, prototype and deferred-implementation language from ordinary operational page headers and several high-noise panels.
- Shortens safety/integration notices to the current state and required action rather than implementation history.
- Simplifies Website Platform overview/governance content and removes tutorial-style guardrail/lifecycle explainer blocks from daily workflows while preserving the actual controls and safety gates.
- Makes `MetricCard.detail` optional so future metrics do not need filler text.
- Preserves concise, contextual workflow information where it is genuinely useful, including Reviews empty-state moderation flow and action consequences.

## Global prevention controls

- Adds `docs/CMS-UI-CONTENT-AND-TYPOGRAPHY-STANDARD.md` as the required standard for new CMS sections/features.
- Adds `docs/V1.0.55-UI-INSPECTION-AUDIT.md` with the keep/remove decisions for the full CMS review.
- Adds `npm run check:ui-hygiene` to enforce the shell cleanup, typography tokens, short page descriptions and absence of developer/roadmap language in static page headers.
- Updates `check:font-floor` to enforce a 12 px minimum across the internal CMS while leaving the separate public Gaming storefront presentation system out of that internal-CMS rule.
- Wires both typography and UI-hygiene checks into `release:gate`.

## Keep / remove rule

The UI keeps current state, required business context, validation, action consequences, trust/provenance and integration-unavailable state. Architecture explanations, roadmap language, tutorials, duplicated descriptions and filler copy belong in docs or source comments instead of the operational interface.

## Data / contracts

No migration. No historical data changes. No new secret. Contract registry pin remains v1.2.0.

## Verification

Run:

```powershell
npm ci
npm run release:finalize
```

`release:finalize` runs the full static `check:*` regression suite, the targeted release gate, the frontend production build and the Worker/API typecheck. It marks `RELEASE-STATE.json` canonical only after all four stages pass. Source validation in this patch session completed with **70/70 static check groups passing**, the targeted release gate passing, and a TypeScript syntax/transpile pass across 225 TS/TSX source files. The frontend build and Worker/API typecheck still require a complete dependency install, so this candidate remains non-canonical.
