# CMS v1.0.19 — build-contract and canonical naming hotfix

This hotfix corrects compile-time regressions found by the deployment-machine Vite/TypeScript build of v1.0.18.

- `StatePanel` loading/error usages now declare the required `state` prop.
- Storefront hero product search uses canonical `NextFGamingProduct.kind`, never a retired/undeclared `category` field.
- UI-derived terminology uses explicit names such as `productKind`/`merchandisingKind` so canonical fields are not confused with legacy model names.
- `check:gaming-build-contract` guards these boundaries before packaging/deployment.

No API, D1 schema, secret, or production route change is introduced.
