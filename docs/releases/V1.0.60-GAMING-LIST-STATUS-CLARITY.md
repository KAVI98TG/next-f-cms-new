# NEXT F CMS v1.0.60 — Gaming List & Status Clarity

Source parent: **v1.0.59**. This is a Pages/frontend-only UI cleanup. It does not add a D1 migration, Worker/API contract change, binding, or secret. The live Contracts Registry remains Production **v1.2.0**.

## Goal

Finish the Gaming operator-UI cleanup at the row/list level. Normal screens should show human-facing names, primary values and actionable state without exposing internal identifiers or repeating healthy-state explanations.

## Changes

- Catalog product rows now show the product name without the slug or internal `nfp_faz_*` identifier. Those identifiers remain searchable and available through product edit/detail workflows.
- Catalog offer counts show the public-count subline only when the public count differs from the total offer count.
- Catalog routing shows the status badge by default and adds a secondary line only for meaningful multi-supplier or multi-route context.
- Catalog offer and supplier-routing list rows no longer print internal offer/provider identifiers under the human-facing name.
- Commerce Analytics product performance now shows product names without internal product IDs.
- Customer Directory rows show the primary order count and net spend only; paid/fulfilled/refund/AOV detail remains available in the customer detail view.
- Commerce Dashboard readiness rows no longer repeat healthy states such as “Queue clear”, “Delivery queue healthy”, or “No active holds”. Supplier error detail still appears when the supplier is not healthy.
- The dashboard all-clear state is reduced to the status itself instead of repeating a sentence that says the same thing.

## Global rule

Normal state = **label + primary value/status**. Secondary row copy appears only when it communicates an exception, mismatch, multi-route/multi-supplier condition, or other non-obvious state that changes an operator decision. Internal IDs are searchable/detail-view information, not normal list-row decoration.

`check:ui-hygiene` now protects these rules across the cleaned Gaming surfaces. `docs/governance/CMS-UI-CONTENT-AND-TYPOGRAPHY-STANDARD.md` contains the permanent rule for future features.
