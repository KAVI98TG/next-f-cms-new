# NEXT F CMS v1.0.61 — Documentation Organization

Canonical parent: **v1.0.60**. Contract registry remains **Production v1.2.0**. This release changes documentation structure and release checks only; it introduces no D1 migration, API contract change, Worker binding change, or new secret.

## Purpose

The repository accumulated current status, continuity rules, verification notes, release history, and general documentation across both the root and a flat `docs/` directory. That made it difficult to distinguish current operator guidance from historical material.

v1.0.61 gives documentation one predictable information architecture and one current entrypoint.

## Changes

- All explanatory project documentation now lives under `docs/`; only the short repository `README.md` remains at root as an entrypoint.
- Adds `docs/README.md` as the documentation index and authority guide.
- Adds `docs/current/` for current status, deployment instructions, and consolidated release notes.
- Moves continuity/project rules and UI/contract standards to `docs/governance/`.
- Moves architecture and integration references to `docs/architecture/`.
- Separates planning records, versioned release records, QA reports, audits, and archived verification material.
- Removes the duplicate root copy of the continuity rulebook.
- Converts `RULESE.txt` into the readable governance document `docs/governance/PROJECT-RULES.md` while preserving the live-contract and migrate-forward rules.
- Archives the v1.0.32 P4 verification record with an explicit historical warning.
- Adds `check:docs` and includes it in the release gate/static suite so old root/flat-document paths cannot silently return.
- Updates source QA scripts and documentation links to the new canonical paths.

## Deployment scope

Pages/frontend only if this version is deployed. No Worker/API deployment and no D1 migration are required.

## Validation

The package must pass `npm run release:finalize` before it becomes canonical. The release finalizer remains the authority for frontend build and Worker/API typecheck status.
