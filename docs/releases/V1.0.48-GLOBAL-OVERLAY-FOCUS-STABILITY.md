# NEXT F CMS v1.0.48 — Global Overlay Focus Stability

## Problem

The shared `Modal` and `Drawer` focus-management effect depended on both `open` and the `onClose` function identity. Most CMS screens pass `onClose` as an inline callback. Typing into a controlled input re-rendered the screen, created a new callback, restarted the effect and focused the first focusable element again. Because the header close button was first in DOM order, focus jumped from the input to the close button while the operator was entering data.

## Fix

- Introduces one shared `useOverlayFocus` focus manager for all CMS `Modal` and `Drawer` instances.
- The focus lifecycle now starts only when the overlay opens and does not restart on ordinary form re-renders.
- The latest close callback is kept in a ref, so Escape still calls current application state without becoming an effect dependency.
- Initial focus prefers an explicit `data-overlay-autofocus` control, then the first non-close interactive control, then the close control only as a last resort.
- Close controls are explicitly `type="button"`, preventing accidental form submission.
- Focus trapping, Escape close, outside-click close and return-to-trigger behavior remain intact.
- The same correction applies globally to shared drawers as well as modals.

## Deployment

Frontend-only release. No Worker/API deployment and no D1 migration are required.

```powershell
npm ci
npm run check:overlay-focus
npm run check:global-ui
npm run build
npm run deploy
```
