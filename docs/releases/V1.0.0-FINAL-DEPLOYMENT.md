# NEXT F CMS V1.0.0 — Final Production Deployment

This is the final deployment runbook for the Production Purity + Auth UX package.

## Preconditions already proven

- Production Cloudflare resources exist and are bound.
- Production Access staff identity is bound and `staff.session.get` has passed.
- D1 migrations and Time Travel restore drill passed.
- Tenant isolation passed against production.
- Public ingress bypass and invalid Turnstile rejection passed.
- Production data-hygiene scan found no auto-cleanable fixture rows. The production acceptance ledger is retained.
- Live `contracts.nextf.lk` is the contract authority. The acceptance runner follows live registry metadata and its referenced production release/schema; it does not pin the registry index itself to an obsolete version.


## 3. Build production frontend

```powershell
$env:VITE_NEXTF_ENVIRONMENT = "production"
$env:VITE_NEXTF_BACKEND_MODE = "production-api"
$env:VITE_NEXTF_API_BASE_URL = "https://cms-api.nextf.lk"
npm run build
```

## 4. Deploy once

```powershell
npx wrangler@latest deploy --config infrastructure/cloudflare/wrangler.production.jsonc
npx wrangler@latest pages deploy dist --project-name nextf-cms --branch main
```

Do not recreate domains, Access apps, D1, R2 or Queues.

## 6. Production acceptance

Authenticate without printing the token:

```powershell
cloudflared access login https://cms-api.nextf.lk
$env:NEXTF_ACCESS_TOKEN = (cloudflared access token -app=https://cms-api.nextf.lk).Trim()
```

Run:

```powershell
npm run acceptance:production:final
```

If the only remaining gate is `public_abuse`, obtain one fresh legitimate production Turnstile token from the real first-party public-site challenge, set it only in the current shell, rerun immediately, then clear it:

```powershell
$env:NEXTF_TURNSTILE_TOKEN = "<fresh-single-use-production-token>"
npm run acceptance:production:final
Remove-Item Env:NEXTF_TURNSTILE_TOKEN
```

Do not reuse a Turnstile token and do not weaken or bypass verification.

The final required result is:

```text
FINAL RESULT: READY FOR V1.0
```

If there are no non-revoked managed Site Connections yet, `managed_site_adapter` is legitimately `not_applicable`. Once the first managed Gaming/site connection exists, real manifest and adapter receipt evidence becomes mandatory.

## 7. Main-site project-request integration

Before the deployed final acceptance can pass `main_site_ingest`, configure one dedicated random integration token on both sides.

CMS Worker secret:

```powershell
npx wrangler@latest secret put NEXTF_MAIN_SITE_INGEST_TOKEN --config infrastructure/cloudflare/wrangler.production.jsonc
```

Website Worker secret:

```text
NEXTF_CMS_API_TOKEN=<same random value>
```

Website variables:

```text
NEXTF_CMS_SUBMISSIONS_ENDPOINT=https://cms-api.nextf.lk/v1/integrations/nextf/project-requests
NEXTF_SITE_ID=nextf-main-website
NEXTF_PROJECT_FORM_ID=nextf-project-request
NEXTF_PROJECT_FORM_VERSION=2026-09-14
NEXT_PUBLIC_SITE_URL=https://nextf.lk
```

The website must send its submission ID as both the HTTP `Idempotency-Key` and `records.submission.idempotencyKey`, and retries must reuse the same submission/lead IDs and payload.

In Cloudflare Access, create a path-specific **Bypass** application/policy for only:

```text
cms-api.nextf.lk/v1/integrations/nextf/project-requests
```

Do not bypass the whole API hostname.

For the runtime acceptance only, load the same integration token into the local operator shell without printing it, run final acceptance, then clear it:

```powershell
$env:NEXTF_MAIN_SITE_INGEST_TOKEN = Get-Clipboard
npm run acceptance:production:final
Remove-Item Env:NEXTF_MAIN_SITE_INGEST_TOKEN -ErrorAction SilentlyContinue
```

The acceptance runner creates a disposable synthetic submission/lead, proves missing/wrong bearer denial, exact replay and changed-payload conflict, verifies private D1 records + Digital Sales projection + audit evidence, and cleans its fixture.
