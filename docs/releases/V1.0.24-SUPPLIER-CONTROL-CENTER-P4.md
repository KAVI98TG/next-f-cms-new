# CMS v1.0.24 — Supplier control center UI

This frontend-only P4 increment redesigns **Gaming Store → Suppliers** for production operations without changing the canonical supplier API or D1 document model.

## UX changes

- Four compact provider-health metrics: connection, balance, last health check, and last catalog sync.
- Two-column control center separating **Runtime & publishing** from **Catalog synchronization**.
- Explicit saved/unsaved configuration state with unload protection.
- Refresh status no longer discards an unsaved configuration draft.
- Catalog families are selectable tiles using the global Gaming kind color system.
- Preview and sync require configuration changes to be saved first; health check remains independent.
- Last preview and last sync summaries are visible beside operational commands.
- Health, Preview, and Sync have a clearer operational hierarchy with queued-worker feedback.
- Canonical architecture and secret-boundary notes are condensed into a compact safeguards row.
- Responsive layouts collapse cleanly for tablet/mobile widths.

## Architecture unchanged

- FazerCards remains the canonical production supplier adapter.
- `FAZERCARDS_API_KEY` remains a `nextf-gaming-api` Worker secret and is never sent to the CMS browser.
- Supplier settings continue to use the existing canonical D1 control documents and Worker command queue.
- No D1 migration, CMS API deployment, Gaming deployment, or new secret is required.
