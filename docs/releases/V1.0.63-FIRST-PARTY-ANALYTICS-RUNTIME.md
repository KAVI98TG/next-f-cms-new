# NEXT F CMS v1.0.63 - First-Party Analytics Runtime

Canonical parent: **v1.0.62**. The full release finalization gate passed and the runtime was deployed to Cloudflare production on 2026-09-24.

## Outcome

Adds the first production-bound reference runtime for the Phase 41 first-party tracking contracts:

- public browser collection at `POST /tracking/browser`;
- authenticated server collection at `POST /tracking/batch`;
- exact Site/origin/environment/event/envelope/SDK validation for the `site_nextf_main` pilot;
- explicit analytics-consent enforcement, bounded payloads, property rejection and stable event-ID deduplication;
- an isolated Cloudflare Queue with a dead-letter queue;
- D1 processing state, hourly aggregates and bounded health counters;
- a supplemental Analytics Engine dataset;
- SDK v1.0.0 at `/sdk/v1/nextf-tracking.js` with bounded batching and retry behavior;
- permission-controlled CMS reporting and tracking-health queries;
- a Platform > Analytics screen.

Tracking observations remain measurement evidence and do not become authoritative Leads, Orders, Payments or other domain facts. Raw event context and properties are not persisted in D1 aggregates. Raw IP addresses are not stored.

## Cloudflare changes

- New custom domain: `tracking.nextf.lk` on the existing `nextf-cms-api` Worker.
- New queue: `nextf-tracking-production-events`.
- New dead-letter queue: `nextf-tracking-production-events-dlq`.
- New Analytics Engine dataset binding: `nextf_tracking_production`.
- New required Worker secret: `TRACKING_SERVER_TOKEN`.
- New forward-only D1 migration: `0002_first_party_tracking.sql`.

## Deployment order

1. Authenticate Wrangler and create both tracking queues.
2. Set `TRACKING_SERVER_TOKEN` on `nextf-cms-api`.
3. Apply D1 migrations remotely to `nextf-cms-production`.
4. Deploy the API Worker.
5. Update the production staff binding with `marketing.analytics.view` and `marketing.tracking.view` as appropriate.
6. Deploy the CMS Pages application.
7. Verify health, SDK delivery, browser ingestion, duplicate handling, queue processing and aggregate reporting.

Do not install the SDK on `nextf.lk` until that Site completes its explicit Contract Registry V1.0.0 to V1.4.0 lifecycle review and declares the Phase 41 collector binding. This release deploys the runtime surface; it does not silently upgrade the Site Manifest or claim pilot data accuracy.
