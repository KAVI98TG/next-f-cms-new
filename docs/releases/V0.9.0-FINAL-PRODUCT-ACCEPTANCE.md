# V0.9.0 - Final Product Acceptance

V0.9.0 closes the infrastructure-independent CMS development phase.

## Acceptance philosophy

The acceptance gate validates business relationships and state invariants, not only whether pages render. It checks that records created through one workflow still reference valid records in the next workflow.

### Platform
- Staff → role references
- unique staff email identities
- role permissions exist in the permission catalog
- manage permissions retain domain read access

### NEXT F Digital
- Lead → Service
- Opportunity → Lead / Client / Service
- Proposal → Opportunity / Client / Service
- Invoice → Client / Project / Subscription
- Project → Client / Service
- Tasks / deliverables / approvals → Project
- Subscription → Client / Service / Project
- Site → Client / Project
- Ticket → Client / Project / Site
- invoice value bounds
- project progress bounds

### Gaming Store
- Supplier product → Supplier
- Storefront product → Supplier + Supplier Product
- Order → Customer + Product + Supplier + Supplier Product
- unique idempotency keys
- valid order economics
- configured minimum-profit safeguard
- Support Case → Order + Customer

### NEXT F Software
- Edition / Release → Product
- Order → Customer + Product + Edition
- License → Customer + Product + Edition + Order
- unique license keys
- activation count ≤ purchased activation limit
- Subscription → License and commercial records
- Download → Customer + Product + Release + License
- Support → Customer + Product + optional License
- Update Check → License + Product

### Shared SaaS layer
- normalized shared accounts are unique by email
- unified payment amounts are valid
- global search index is available
- operations center evaluates successfully

## Infrastructure state

Production infrastructure remains deliberately marked **Deferred**. V0.9.0 does not pretend that production authentication, databases, storage, provider webhooks or delivery endpoints exist before they are actually configured.
