# CMS v1.0.28 — Customer 360 profile UI + avatars

## Scope

Frontend-only Customer 360 redesign for Gaming Store Customers. The canonical customer snapshot, Google account model, D1 namespaces, marketing consent rules, order ownership, support/risk context and permissions remain unchanged.

## UI changes

- canonical Google account `avatarUrl` is rendered in the customer directory and Customer 360 drawer
- avatar rendering accepts HTTPS only and falls back to customer initials when missing or when the remote image fails
- customer table has richer identity rows and clearer Google/Guest account state
- top customer metrics are compact and Repeat / Marketing cards act as quick filters
- Customer 360 drawer has a larger profile header with identity, lifecycle and marketing state
- commerce summary shows orders, net spend, last purchase and average order value
- identity, marketing consent and operational context are grouped into compact panels
- order history has denser rows and a dedicated empty state
- customer drawer has a wider responsive layout while the shared Drawer default remains unchanged

## Security / privacy boundaries unchanged

- Customer PII still requires `gaming.orders.manage`
- profile images come only from the canonical account snapshot; the CMS does not query Google directly
- image URLs are accepted only when HTTPS
- marketing consent remains separate from transactional order/payment/delivery/refund/support communication
- no D1 migration, secret, CMS Worker change, Gaming API deployment or Gaming storefront deployment is required
