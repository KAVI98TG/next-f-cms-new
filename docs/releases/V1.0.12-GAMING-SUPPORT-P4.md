# CMS v1.0.12 — Gaming Support Cases & Order Disputes (P4 RC)

The Gaming Support surface now reads canonical support cases from shared D1 instead of the old local prototype repository.

## Staff surface

`/gaming-store/support` provides:

- order-linked case creation;
- issue category and normal/high/urgent priority;
- active status and SLA visibility;
- assign-to-me / unassign operations;
- internal staff notes;
- customer-facing support messages;
- safe evidence-reference metadata;
- live order/payment/fulfillment/refund/risk context.

The route and server query require the existing `gaming.orders.manage` permission so internal case messages are not exposed to generic `gaming.read` accounts.

## Command boundary

The CMS Worker holds `GAMING_CMS_SUPPORT_TOKEN` and forwards only support create/command actions to the Gaming API. Browser code receives neither this secret nor the operations/commerce credentials. CMS command idempotency remains the outer operator-command boundary and both CMS and Gaming audit trails retain the real staff account principal.

## Customer communication

Customer messages are canonical case messages first. The Gaming event/outbox system then delivers them as transactional email when the existing email provider is enabled. Internal notes do not enter the notification outbox.

## Evidence boundary

This release intentionally does not implement binary support attachments. Evidence records contain safe metadata/reference values only. Payment reconciliation secrets remain in Finance and customer delivery/recovery secrets remain outside support projections.
