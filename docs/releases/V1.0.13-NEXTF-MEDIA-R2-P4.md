# CMS v1.0.13 — NEXT F Media Service + Cloudflare R2 (P4 RC)

This increment establishes the owned NEXT F media boundary for Gaming merchandising and private support evidence.

## Architecture

- Dedicated private R2 bucket: `nextf-media-production`.
- CMS Worker binding: `MEDIA`.
- Public asset delivery: `https://media.nextf.lk/a/<assetId>` through the CMS Worker. The bucket itself remains private and `r2.dev` must not be enabled.
- Direct browser uploads: short-lived S3-compatible presigned PUT URLs, restricted to the declared `Content-Type`.
- Uploads land under `staging/`; finalization validates byte size and content type, then promotes the object to a different served key and deletes staging.
- Public Gaming media uses `public/gaming/*` keys.
- Private support evidence uses `private/support/*` keys and is downloaded only through the Cloudflare-Access-authenticated CMS API.
- Canonical metadata is stored in shared D1 under `nextf.media.asset`.

## Supported media purposes

- `gaming_product_artwork` — public images, `gaming.products.manage`.
- `gaming_family_artwork` — public images, `gaming.products.manage`.
- `gaming_family_hero` — public images, `gaming.products.manage`.
- `gaming_storefront_hero` — public images, `gaming.products.manage`.
- `support_evidence` — private image/PDF evidence, `gaming.orders.manage`.

Public artwork accepts JPEG, PNG, WebP and GIF up to 10 MiB. Support evidence additionally accepts PDF up to 15 MiB.

## Deployment / activation

Create the bucket once if it does not already exist:

```powershell
npx wrangler@latest r2 bucket create nextf-media-production
```

Create an R2 S3 API token with **Object Read & Write**, scoped only to `nextf-media-production`. Store the Account ID, Access Key ID and Secret Access Key as CMS Worker secrets:

```powershell
npx wrangler@latest secret put NEXTF_MEDIA_R2_ACCOUNT_ID --config infrastructure/cloudflare/wrangler.production.jsonc
npx wrangler@latest secret put NEXTF_MEDIA_R2_ACCESS_KEY_ID --config infrastructure/cloudflare/wrangler.production.jsonc
npx wrangler@latest secret put NEXTF_MEDIA_R2_SECRET_ACCESS_KEY --config infrastructure/cloudflare/wrangler.production.jsonc
```

Apply the browser upload CORS policy:

```powershell
npx wrangler@latest r2 bucket cors set nextf-media-production --file infrastructure/cloudflare/media-r2-cors.production.json
npx wrangler@latest r2 bucket cors list nextf-media-production
```

Expire abandoned/reused staging uploads after one day:

```powershell
npx wrangler@latest r2 bucket lifecycle add nextf-media-production nextf-media-staging-cleanup staging/ --expire-days 1
npx wrangler@latest r2 bucket lifecycle list nextf-media-production
```

Do not add a blanket lifecycle expiry to `public/` or `private/support/`. Retention/deletion for canonical media needs an explicit later governance policy.

Deploy the CMS API Worker after the bucket, token, CORS and lifecycle are ready. The Worker custom-domain configuration owns `media.nextf.lk`.

## Security rules

- Presigned URLs are treated as bearer tokens and expire after five minutes.
- A reusable presigned URL points only at a staging key; it cannot overwrite the immutable served key after finalization.
- Finalization fails closed if object size or content type does not exactly match the upload request.
- Invalid staging objects are deleted.
- Private support evidence never receives a public media URL.
- Private evidence download requires a verified Cloudflare Access staff principal with `gaming.orders.manage`.
- Support case linking validates the media asset is finalized, private, `support_evidence`, and owned by the exact case/order.
- R2 API credentials never enter browser code.

## CMS integration

NEXT F Media upload controls are integrated into:

- Gaming product artwork;
- homepage hero artwork;
- game-family card artwork;
- game-family hero artwork;
- Support & Disputes private evidence.

Legacy external HTTPS artwork URLs remain compatible, but NEXT F Media is the preferred owned asset source.

## No D1 schema migration

Media metadata uses the existing `app_documents` store, so this release adds no SQL migration.
