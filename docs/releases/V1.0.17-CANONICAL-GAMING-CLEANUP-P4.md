# CMS v1.0.17 — Canonical Gaming cleanup + Customer 360

This P4 increment retires the remaining production-facing v0.5 Gaming CMS surfaces and makes the canonical P4 commerce model the only production operator path.

## Navigation cleanup

Production Gaming navigation is now:

- Dashboard
- Live Operations
- Catalog
- Storefront
- Pricing
- Promotions
- Suppliers
- Customers
- Finance
- Analytics
- Support

Legacy `Products`, `Orders`, and `Settings` links are retired. Their URLs redirect to canonical destinations. `Digital Catalog vNext` is now simply `Catalog`.

## Canonical Customer 360

The Customers page now derives customer intelligence from shared-D1 canonical records:

- verified Google customer accounts;
- guest purchases by receipt email;
- orders and payment state;
- completed refunds;
- support cases;
- risk assessments;
- promotion usage;
- explicit marketing consent.

The page includes account type, lifecycle, order counts, verified/fulfilled purchases, net spend, average order value, favorite product, support/risk context, marketing status, and safe order history. Customer detail requires `gaming.orders.manage`.

Transactional communications remain independent of promotional marketing consent.

## Legacy v0.5 retirement

Production staff state no longer reads or writes `nextf.v0.5.gaming.*` through the CMS API. Existing stored documents are not deleted and remain available for recovery/history if required.

The production Dashboard, Pricing, Supplier control plane, Catalog, global search and shared centers no longer depend on the legacy Gaming repository.

## Supplier surface

The placeholder local `Add supplier` registry has been removed. FazerCards production controls remain. Future suppliers must enter through the canonical supplier adapter/routing model rather than a UI-only registry.

## No migration or new secret

This release does not require a D1 schema migration or a new Cloudflare secret.
