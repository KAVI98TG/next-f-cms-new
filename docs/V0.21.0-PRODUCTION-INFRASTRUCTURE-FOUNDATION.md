# V0.21.0 — Production Infrastructure Foundation

## Scope

V0.21.0 implements the provider-specific production adapter package for the **main internal CMS/shared backend boundary** while keeping the Customer Workspace frontend as a separate future project.

## Cloudflare architecture

- Workers: API edge/runtime.
- D1: durable business documents, audit, idempotency, staff identity bindings, outbox and public projection metadata.
- R2: binary/file objects; D1 stores metadata/reference only.
- Queues: asynchronous integration/event delivery. Consumers must be idempotent because queue delivery is at-least-once; configure a DLQ for failed deliveries.
- Workflows: durable multi-step provisioning, export/offboarding and other long-running stateful operations.
- Cloudflare Access: staff perimeter. The Worker validates the Access JWT and then maps the verified identity to an active staff identity binding/RBAC record.
- Workers Rate Limiting + Turnstile: low-trust `nextf.lk` mutation protection.
- Workers Secrets: encrypted provider/service credentials.
- Workers observability: logs/traces in deployment environments.

## D1 recovery

Use migrations for schema changes and D1 Time Travel for point-in-time recovery. Longer retention should use controlled database exports to a restricted R2 backup bucket. Restore must be tested, not only documented.

## Important fail-closed rule

The Worker scaffold returns a non-success response for staff business routes until durable production domain handlers are bound. This is deliberate. V0.21 must not masquerade an infrastructure skeleton as a functioning production business API or silently route production traffic into browser localStorage.

## Remaining deployment work

Source implementation cannot create account-specific Cloudflare resources or secrets without NEXT F's Cloudflare credentials. Before production acceptance:

1. create staging and production Workers/D1/R2/Queues;
2. configure Access application/audience;
3. set secrets;
4. apply D1 migrations;
5. bind real domain handlers/repositories;
6. connect Contracts Registry and managed-site credentials;
7. run D1 restore drill;
8. run runtime/build/browser acceptance.
