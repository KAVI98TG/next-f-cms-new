# V0.10.0 Architecture Completion

## Goal

Close every CMS application gap identified by comparing V0.9.0 against `NEXT-F-CMS-FINAL-ARCHITECTURE.md`, without starting Cloudflare infrastructure work.

## Platform additions

- Organizations / Workspaces
- Domains
- Security Center
- System Logs
- Backup Management
- Cleanup / Retention

These are real browser-persistent operational modules with auditing and permission boundaries, not placeholder folders.

## NEXT F Digital additions

- Service Add-ons
- Project Templates
- Billing Adjustments
- Client Portal Access
- Digital Business Settings

Digital settings are wired into the existing lifecycle rather than being decorative configuration.

## Repository refactor

### NEXT F Digital

`src/next-f/data/digitalStore.ts` is now a compatibility facade. Domain behavior is split across repositories for sales, clients, services, projects, billing, sites, support, automation and activity.

### Gaming Store

`src/gaming-store/data/gamingStore.ts` is now a compatibility facade. Supplier, catalog, order, settings and support behavior is separated into repositories.

### NEXT F Software

`src/software/data/softwareStore.ts` is now a compatibility facade. Catalog, releases, commercial lifecycle, licensing, delivery, settings and support behavior is separated into repositories.

## Architecture rule

A clean folder tree is not enough. A domain is considered separated only when its behavior and persistence responsibilities are owned by focused repositories/services instead of one hidden oversized store.

## Infrastructure boundary

No D1, R2, Workers, Wrangler, production authentication, payment, email, supplier or software-delivery infrastructure was added in this release. Those remain intentionally deferred.
