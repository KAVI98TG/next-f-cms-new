# V0.22.0 — Lifecycle, Offboarding, Portability & Production Acceptance

## Purpose

This phase completes the **main internal CMS source roadmap** while keeping `workspace.nextf.lk` as a separate future project.

## Customer/service exit

Offboarding is a governed plan, not a billing side effect. The plan records customer/workspace scope, memberships, managed sites, projects, services, overdue invoice evidence and active/past-due subscription evidence.

An overdue invoice or past-due subscription **must never automatically shut down a customer website**. Workspace/customer-service restrictions and managed-site suspension/revocation are separate staff decisions with audit evidence.

Recommended sequence:

1. create offboarding plan;
2. staff review;
3. transition workspace to read-only/suspended where appropriate;
4. suspend customer memberships;
5. prepare customer portability export;
6. confirm asset ownership/transfer obligations;
7. explicitly suspend/revoke/transfer managed-site connection as agreed;
8. revoke memberships;
9. close workspace;
10. retain internal/audit records according to policy.

## Portability

Exports may include customer-visible/owned website content references, eligible project/deliverable records, permitted billing/contract records, customer-uploaded file metadata and customer-visible activity.

Exports exclude staff notes, security logs, credentials/secrets, infrastructure internals, other-tenant data and internal cost/margin information. Export artifacts require an integrity checksum and bounded expiry.

## Asset ownership

Ownership is evidence-driven. A domain, hosting account, analytics property, advertising account, Search Console property or content asset must not be classified as customer/NEXT F-owned merely because NEXT F is technically connected to it. The project/agreement and explicit evidence determine ownership and portability.

## Contract migration

A managed Site Contract upgrade is a separate plan. It starts fail-closed and cannot be scheduled until a trusted target Registry snapshot and official compatibility validation are available. A version string alone is not migration authorization.

## Demo and retention

Demo environments remain synthetic-only and have expiry/reset/revocation controls. Production infrastructure schedules expiry/retention/idempotency sweep events through the queue layer; durable domain consumers still need deployment binding.

## Production acceptance ledger

V0.22 introduces explicit critical release gates. **The CMS may not be called production V1.0 merely because source regression tests pass.** Critical external gates include:

- locked dependency install + TypeScript/Vite build;
- browser visual/runtime smoke;
- deployed Workers/D1/R2/Queues/Rate Limiter;
- Access authentication and staff mapping;
- D1 migrations;
- restore drill;
- deployed tenancy/security testing;
- Turnstile/rate-limit/idempotency public ingress;
- authoritative Contract Registry + real Site Manifest;
- managed-site production adapters;
- real offboarding/export/revocation end-to-end test.

V0.22.0 is therefore the **main CMS source-completion candidate**, not a fabricated production deployment claim.
