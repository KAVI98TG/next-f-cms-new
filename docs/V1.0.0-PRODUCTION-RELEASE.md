# NEXT F CMS V1.0.0 Production Release

## Release objective

V1.0.0 is the production release package for `cms.nextf.lk` and `cms-api.nextf.lk`. It preserves the existing Cloudflare deployment and adds a fail-closed production login/bootstrap experience, durable public idempotency, scheduled maintenance/retention handling, and one guarded production acceptance runner.

## Existing production evidence carried into V1

The production deployment has already proven the following before this package was cut:

- Cloudflare Worker, Pages, D1, R2, Queue/DLQ, rate limiter, cron and custom domains deployed.
- Cloudflare Access production application and exact staff subject binding verified.
- `staff.session.get` returned `ok: true` with `cloudflare-access` assurance and the canonical Super Admin permission set.
- production browser smoke and deep-route refresh passed.
- D1 Time Travel restore drill passed and the staff binding survived restore.
- tenant isolation passed with valid-scope 200, wrong-organization 403 `WORKSPACE_SCOPE_MISMATCH`, denial audit evidence and fixture cleanup.
- anonymous `/v1/public/*` ingress is intentionally outside Access while staff routes remain protected.
- invalid Turnstile submissions are rejected by the Worker.

## V1 source additions

- `ProductionBootstrap` renders a branded login/session verification screen before any production data is loaded.
- `/auth/complete` completes API-host Access authentication and redirects to the CMS origin.
- public exact-idempotency replay is resolved from D1 before a second Turnstile redemption, respecting Turnstile single-use semantics.
- scheduled and staff-triggered maintenance share one runtime path for demo expiry, audit retention, terminal outbox retention and idempotency expiry.
- production configuration includes the confirmed non-secret production bindings and retention policy values; Worker secrets remain outside source.
- `npm run acceptance:production` performs the remaining runtime acceptance with disposable guarded fixtures and generates JSON/Markdown evidence.

## Operator flow

From the final package, validate the source first:

```powershell
npm ci
npm run acceptance:source
```

Deploy the V1 Worker/frontend before runtime acceptance because the remaining 4D–4F tests exercise the new V1 runtime handlers.

A fresh legitimate Turnstile token is required to close the public idempotency runtime gate. Set it only in the current shell and rerun immediately:

```powershell
$env:NEXTF_TURNSTILE_TOKEN = "<fresh-single-use-production-token>"
npm run acceptance:production
Remove-Item Env:NEXTF_TURNSTILE_TOKEN
```

Deploy the changed V1 Worker and frontend after source acceptance:

```powershell
$env:VITE_NEXTF_ENVIRONMENT = "production"
$env:VITE_NEXTF_BACKEND_MODE = "production-api"
$env:VITE_NEXTF_API_BASE_URL = "https://cms-api.nextf.lk"
npm run build
npx wrangler@latest deploy --config infrastructure/cloudflare/wrangler.production.jsonc
npx wrangler@latest pages deploy dist --project-name nextf-cms --branch main
```

Then run the strict deployed acceptance (with a fresh Turnstile token set in the shell):

```powershell
npm run acceptance:production:final
```

Only `FINAL RESULT: READY FOR V1.0` closes the release.

## Managed-site adapter gate

If production has no non-revoked managed Site Connection, `managed_site_adapter` is recorded as `not_applicable`, not fabricated as passed. The acceptance gate must be reopened before the first managed site is activated. For a real connected site, provide real evidence URLs:

```powershell
$env:NEXTF_MANAGED_SITE_MANIFEST_URL = "https://.../nextf.site.json"
$env:NEXTF_MANAGED_SITE_RECEIPT_URL = "https://.../receipt.json"
```

The Gaming site is expected to be the next integration stream and is a natural candidate for the first managed-site proof.

## Acceptance artifacts

Each run writes:

- `artifacts/production-acceptance/latest.json`
- `artifacts/production-acceptance/latest.md`
- timestamped evidence files for the individual run

Acceptance fixtures are uniquely namespaced and cleaned in `finally` paths. Production secrets are never written into evidence files.
