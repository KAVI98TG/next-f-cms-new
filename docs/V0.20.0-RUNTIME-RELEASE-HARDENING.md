# V0.20.0 — Runtime & Release Hardening

## Purpose

V0.20.0 closes the source-side portion of Phase 8.5 and creates a deterministic release gate before production infrastructure work.

## What changed

- Central release metadata advanced to `0.20.0`.
- The V0.19 first-party integration regression gate is forward-compatible with later releases.
- A dedicated runtime/release-readiness gate verifies the locked dependency graph, build commands, TypeScript/Vite configuration and release artifacts.
- Phase 8.5 visual/runtime acceptance is explicitly separated from source-level QA.

## Dependency-backed build attempt

The locked install was attempted with `npm ci` in the execution environment. Outbound package retrieval did not complete and left only a partial `node_modules` tree, so that tree was discarded. A dependency-backed Vite build therefore cannot be truthfully recorded as passed in this environment.

This is an **environmental acceptance blocker**, not a substitute for the required build. In an internet-enabled CI/development environment the release gate remains:

```bash
npm ci
npm run build
npm run dev -- --host 0.0.0.0
```

Then visually smoke-test Platform, NEXT F Digital and Website Platform at desktop/tablet/mobile widths and review browser console/runtime errors.

## Release rule

V0.20 source hardening may be used as the base for infrastructure implementation, but **V1.0 production acceptance must remain blocked until the dependency-backed build and browser smoke pass are executed in the deployment environment**.
